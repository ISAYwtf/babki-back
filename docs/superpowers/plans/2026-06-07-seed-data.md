# Seed Data System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create `npm run seed` that wipes the dev database and populates it with 4 months of realistic financial data (user, 2 accounts, 6 categories, 2 limits, 19 transactions, 2 debts).

**Architecture:** Bootstrap NestJS via `NestFactory.createApplicationContext(AppModule)` — no HTTP server. Call existing services in dependency order. Accounts are inserted directly via Mongoose model to avoid a phantom snapshot at today's date that would shadow the correct current balance. All other entities go through real services so the snapshot invariant is automatically maintained.

**Tech Stack:** NestJS 11, Mongoose 9, ts-node 10, tsconfig-paths, bcrypt, date-fns

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from '../app.module';
import { runSeeders } from './seeds/index';

async function bootstrap() {
  if (process.env.NODE_ENV !== 'development') {
    throw new Error(
      `Seed script can only run in NODE_ENV=development. Current: ${process.env.NODE_ENV ?? 'unset'}`,
    );
  }

  const app = await NestFactory.createApplicationContext(AppModule, {
    logger: ['error', 'warn'],
  });

  try {
    await runSeeders(app);
    console.log('\n✅ Seeding complete');
  } catch (err) {
    console.error('\n❌ Seeding failed:', err);
    process.exit(1);
  } finally {
    await app.close();
  }
}

bootstrap();
```

## Task 5: Accounts seeder (`02-accounts.ts`)

**Files:**
- Create: `src/database/seeds/02-accounts.ts`

**Why direct model insert:** `AccountsService.create()` inserts an initial snapshot at `new Date()` (today). Because `findByAccountId` returns the most recent snapshot with `date <= requestedDate`, this June-07 snapshot would be returned when querying the current balance — showing only the June net activity (4500) instead of the full balance (15040). Inserting accounts directly via the model skips the initial snapshot; all snapshots are built organically by the transaction seeder.

- [ ] **Create `src/database/seeds/02-accounts.ts`:**

```typescript
import { INestApplicationContext } from '@nestjs/common';
import { getModelToken } from '@nestjs/mongoose';
import { Model, Types } from 'mongoose';
import { Account } from '../../modules/accounts/schemas/accounts.schema';

export async function seedAccounts(
  app: INestApplicationContext,
  userId: string,
) {
  const accountModel = app.get<Model<Account>>(getModelToken(Account.name));

  const [balance, saving] = await Promise.all([
    accountModel.create({ userId: new Types.ObjectId(userId), type: 'balance' }),
    accountModel.create({ userId: new Types.ObjectId(userId), type: 'saving' }),
  ]);

  return {
    balanceAccountId: balance._id.toString(),
    savingAccountId: saving._id.toString(),
  };
}
```

```typescript
const CATEGORIES = [
  { name: 'Food & Dining', color: '#FF6B6B' },
  { name: 'Transport', color: '#4ECDC4' },
  { name: 'Entertainment', color: '#45B7D1' },
  { name: 'Utilities', color: '#FFA07A' },
  { name: 'Health', color: '#98D8C8' },
  { name: 'Shopping', color: '#DDA0DD' },
] as const;

export async function seedCategories(
  app: INestApplicationContext,
  userId: string,
): Promise<CategoryMap> {
  const categoriesService = app.get(ExpenseCategoriesService);
  const result: CategoryMap = {};

  for (const cat of CATEGORIES) {
    const created = await categoriesService.create(userId, { name: cat.name, color: cat.color });
    result[cat.name] = String(created._id);
  }

  return result;
}
```

## Task 7: Transactions seeder (`05-transactions.ts`)

**Files:**
- Create: `src/database/seeds/05-transactions.ts`

**Important:** Transactions must be created in strict chronological order. Each call to `IncomesService.create()` / `ExpensesService.create()` / `SavesService.create()` internally calls `findOrCreateByAccountId` (creates the month snapshot if needed) then `recalculateSnapshotsFromDate` (propagates the amount to all later snapshots). The order within a month matters too — income must come before saves within the same month, because `SavesService` checks `sourceSnapshot.amount >= amount` before proceeding.

`ExpensesService` and `IncomesService` resolve the balance account automatically via `ensureUserExists(userId, 'balance')`. `SavesService` resolves the saving account automatically; `balanceAccountId` is passed as `sourceAccountId` in the DTO.

- [ ] **Create `src/database/seeds/05-transactions.ts`:**

## Snapshot count rationale (Task 10 verification)

| Account | Month snapshots created | Count |
|---|---|---|
| Balance | Mar-01, Apr-01, May-01, Jun-01 | 4 |
| Saving | Mar-01, Apr-01, May-01 | 3 |
| **Total** | | **7** |

Saving account gets no June snapshot because no save transaction is created in June. The balance at the saving account stays at 1500 (last snapshot May-01).
